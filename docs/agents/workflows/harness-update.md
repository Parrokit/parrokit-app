# Harness Update Workflow

## 업데이트 트리거

- 같은 실수 또는 리뷰 코멘트가 2회 이상 반복될 때
- 프로젝트 구조 또는 기술 스택이 실제로 변경될 때
- 팀 합의 규칙이 새로 생겼을 때

## 업데이트 원칙

- 필요한 문장만 최소 수정한다.
- 모호한 권장 표현보다 강제 규칙을 우선한다.
- 같은 규칙은 한 곳에만 유지한다.
- 긴 예시보다 체크리스트를 우선한다.

## 변경 절차

1. 변경 목적을 1줄로 작성한다.
2. 수정 파일을 최소화한다.
3. `AGENTS.md`를 우선 수정하고, 필요할 때만 workflow 또는 rules 문서를 수정한다.
4. 영향 범위를 확인한다.
5. 변경 내용을 커밋한다.
6. 커밋 또는 PR 본문에 변경 이유를 1줄로 기록한다.
