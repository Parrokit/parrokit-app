# Captioning(자동자막) 기능 FRD (초안)

## 1. 목적
로컬/생성 콘텐츠에 대해 자동자막을 생성·수정·저장하고, 쉐도잉 학습으로 빠르게 연결한다.

## 2. 문제 정의
- 현재 clip-editor에 자동자막과 컬렉션 관련 책임이 혼재되어 기능 경계가 불명확하다.
- 생성 스튜디오와의 연계 시, 입력 미디어 전달/복귀 컨텍스트 관리가 명시적으로 필요하다.

## 3. 범위 (MVP)
### In Scope
- 자동자막 생성 실행(입력: 로컬 미디어 URI)
- 자막 결과 확인/수정/재시도
- 생성 스튜디오 연계 진입/복귀
- 컬렉션 저장 트리거 호출(컬렉션 생성 자체는 별도 기능)
- 구현 경로(권장): `feature/content-studio/captioning`
- 라우트: `/content-studio/captioning`

### Out of Scope
- TTS/Video 생성 자체 로직
- 컬렉션 도메인 상세 생성/편집 로직
- 고급 자막 스타일 편집(테마 에디터 수준)

## 4. 핵심 사용자 플로우
1. 사용자가 `/content-studio/captioning` 진입
2. 입력 미디어 로컬 URI 수신 또는 콘텐츠 제작으로 리다이렉트
3. 자동자막 생성 실행
4. 결과 확인 후 수정/재생 검수
5. 실패 시 재시도 또는 수동 보정
6. 완료 결과를 저장하고 컬렉션 저장 트리거 호출

## 5. 기능 요구사항 (FR)
- FR-CAP-01: 화면은 로컬 미디어 URI payload를 받아 자동자막 생성에 사용한다.
- FR-CAP-02: 자동자막 화면에서 `콘텐츠 제작` 버튼으로 `/content-studio/hub` 이동이 가능해야 한다.
- FR-CAP-03: 스튜디오에서 생성 완료 후 전달된 로컬 URI로 자동자막 화면에 즉시 복귀/점프해야 한다.
- FR-CAP-04: 자동자막 생성 상태(대기/처리중/완료/실패)를 사용자에게 표시한다.
- FR-CAP-05: 자막 생성 실패 시 재시도와 수동 보정 경로를 제공한다.
- FR-CAP-06: 자동자막 완료 결과는 컬렉션 기능에 저장 요청을 전달할 수 있어야 한다.
- FR-CAP-07: Captioning은 생성(TTS/Video) 및 컬렉션과 독립 배포 가능한 경계를 유지한다.

## 6. 비기능 요구사항 (NFR)
- NFR-CAP-01: 화면 이탈/복귀 시 로컬 URI와 편집 중 자막 상태를 복구 가능해야 한다.
- NFR-CAP-02: 실패 원인을 최소 `네트워크/처리실패/입력오류`로 구분 표시해야 한다.
- NFR-CAP-03: 생성 스튜디오 왕복 시 내비게이션 컨텍스트 손실이 없어야 한다.
- NFR-CAP-04: 컬렉션 저장 호출은 멱등 처리(중복 저장 방지) 정책을 가져야 한다.

## 7. 수용 기준 (AC)
- AC-CAP-01: 로컬 미디어 URI를 전달받아 자동자막을 정상 생성할 수 있다.
- AC-CAP-02: 자동자막 화면에서 콘텐츠 제작으로 이동 후, 생성 완료 시 동일 세션 맥락으로 복귀한다.
- AC-CAP-03: 자막 실패 시 재시도 또는 수동 보정으로 작업을 계속할 수 있다.
- AC-CAP-04: 완료된 자막 결과를 컬렉션 저장 단계로 넘길 수 있다.
- AC-CAP-05: 생성/컬렉션 기능이 비활성화되어도 Captioning 단독 동작이 가능하다.

## 8. 경계 설계 권장
- 자동자막 기능 단위(Captioning): 미디어 입력, 자막 생성/편집, 저장 요청 트리거까지 담당
- 컬렉션 생성 단위(Collection): 저장소 구조, 메타데이터, 중복/버전 정책 담당
- 연결 방식: Captioning -> Collection Service 인터페이스 호출(직접 DB 조작 금지)
