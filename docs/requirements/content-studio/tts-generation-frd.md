# TTS 생성 기능 FRD (초안)

## 1. 목적
사용자가 텍스트를 입력해 학습용 음성을 생성하고, 생성 결과를 독립적으로 저장/활용할 수 있게 한다.

## 2. 문제 정의
- 현재는 사용자 촬영/업로드가 필요해 쉐도잉 진입 마찰이 크다.
- 문장 반복 학습 목적 사용자에게 콘텐츠 준비 비용이 과도하다.

## 3. 범위 (MVP)
### In Scope
- 텍스트 입력 기반 TTS 생성
- 텍스트 길이(문자 수) 제한 정책 적용(최대 240자)
- TTS 타입(음성 타입) 선택
- 생성 결과 로컬 자동 저장 및 재사용
- 자동자막 화면에서 `콘텐츠 제작` 버튼으로 생성 스튜디오 리다이렉트(IA 일관성)
- 구현 경로: `feature/content-studio/tts`
- 라우트: `/content-studio/tts` (스튜디오 진입 허브는 `/content-studio/hub`)

### Out of Scope
- 고급 음색 편집(보이스 클로닝, 감정 커브 수동 편집)
- 배치 대량 생성 및 고급 편집 스튜디오 기능

## 4. 핵심 사용자 플로우
1. 사용자가 텍스트 입력
2. 텍스트 길이 제한 검증
3. TTS 타입 선택
4. TTS 생성 실행
5. 생성 결과를 사용자 로컬에 자동 저장
6. 저장된 결과를 이후 자동자막/쉐도잉 또는 컬렉션에서 활용

## 5. 기능 요구사항 (FR)
- FR-TTS-01: 자동자막 시작 화면에서 `텍스트로 생성` 진입 가능
- FR-TTS-02: 텍스트 입력은 문자 수 제한 규칙을 적용한다.
- FR-TTS-03: 사용자는 TTS 생성 전 타입(음성 타입)을 선택할 수 있다.
- FR-TTS-04: 생성 성공 시 결과를 사용자 로컬에 자동 저장한다.
- FR-TTS-05: 저장된 결과는 기존 컬렉션 자동재생에서 동일하게 재생 가능하다.
- FR-TTS-06: TTS 생성 기능은 Video 생성 기능과 독립적으로 동작한다.
- FR-TTS-07: 생성 스튜디오는 자동자막 화면과 분리된 독립 화면으로 동작한다.

## 6. 비기능 요구사항 (NFR)
- NFR-TTS-01: 생성 요청 후 첫 결과 표시 목표 시간 정의 필요
- NFR-TTS-02: 실패 원인(네트워크/생성/자막)을 사용자에게 구분 표시
- NFR-TTS-03: 생성 비용은 앱 화폐 `패롯` 단위로 차감한다.
- NFR-TTS-04: 처리 중 앱 이탈 시 복구 가능한 상태 저장 필요

## 7. 수용 기준 (AC)
- AC-TTS-01: 텍스트 길이 제한을 초과하면 생성이 차단되고 안내 메시지가 표시된다.
- AC-TTS-02: 타입을 선택해 TTS 생성이 가능하다.
- AC-TTS-03: 생성 성공 결과가 사용자 로컬에 자동 저장된다.
- AC-TTS-04: 저장된 결과가 컬렉션 자동재생 대상에 포함된다.
- AC-TTS-05: 생성 시 패롯 차감 내역이 반영된다.

## 8. 오픈 이슈
- 문자 수 제한은 최대 240자로 확정
- TTS 타입 목록과 타입별 패롯 단가 확정 필요
- 자동자막/쉐도잉 연결 트리거를 자동/수동 중 어느 방식으로 둘지 확정 필요
