# Community 차단 기능 FRD (초안)

## 1. 목적
커뮤니티에서 원치 않는 사용자와의 상호작용을 즉시 차단해 사용자 안전과 피드 품질을 높인다.

## 2. 문제 정의
- 원치 않는 사용자 콘텐츠를 즉시 회피할 수단이 부족하다.
- 상호작용 차단 정책이 없어 반복적인 불편이 누적된다.

## 3. 범위 (MVP)
### In Scope
- 사용자 차단/차단 해제
- 차단 목록 조회
- 차단 즉시 피드/상호작용 반영
- 차단 이력 최소 감사 필드 저장

### Out of Scope
- 자동 제재(자동 정지/자동 삭제)
- 운영자 콘솔 상세 UI
- 법적 요청 처리 워크플로

## 4. 핵심 사용자 플로우
1. 사용자가 게시글/댓글/프로필의 더보기 메뉴 진입
2. `차단` 선택
3. 즉시 상호작용 차단 및 피드 반영
4. 설정의 차단 목록에서 해제 가능

## 5. 기능 요구사항 (FR)
- FR-BLOCK-01: 사용자는 다른 사용자를 차단할 수 있어야 한다.
- FR-BLOCK-02: 차단된 사용자의 게시글/댓글은 기본 피드에서 노출되지 않아야 한다.
- FR-BLOCK-03: 차단된 사용자와의 직접 상호작용(댓글 작성, 멘션, DM 진입)은 제한되어야 한다.
- FR-BLOCK-04: 사용자는 설정 화면에서 차단 목록을 조회하고 차단 해제할 수 있어야 한다.
- FR-BLOCK-05: 이미 차단된 사용자 재차단 요청은 멱등 성공으로 처리해야 한다.
- FR-BLOCK-06: 차단/해제 이력은 감사 추적이 가능하도록 최소 필드를 저장해야 한다.

## 6. 데이터 계약(초안)
### 차단(Block)
- blockId: string
- blockerUserId: string
- blockedUserId: string
- createdAt: timestamp
- releasedAt: timestamp?
- status: enum(`active`, `released`)

## 7. 예외/에러 규칙
- 이미 차단된 사용자를 다시 차단하면 성공으로 처리하되 멱등 응답을 반환한다.
- 네트워크 실패 시 재시도 액션을 제공한다.

## 8. 비기능 요구사항 (NFR)
- NFR-BLOCK-01: 차단 반영은 사용자 액션 후 즉시 UI에서 체감 가능해야 한다.
- NFR-BLOCK-02: 차단 관계 데이터는 개인정보 접근 권한 정책을 준수해야 한다.

## 9. 수용 기준 (AC)
- AC-BLOCK-01: 특정 사용자를 차단하면 해당 사용자의 콘텐츠가 피드에서 즉시 숨김 처리된다.
- AC-BLOCK-02: 차단 목록에서 해제하면 이후 해당 사용자의 콘텐츠가 다시 노출될 수 있다.
- AC-BLOCK-03: 차단된 사용자와의 직접 상호작용은 제한된다.
- AC-BLOCK-04: 재차단 요청은 오류 없이 멱등 처리된다.

## 10. 오픈 이슈
