# Community 게시글 알림 FRD (초안)

## 1. 목적
커뮤니티 게시글에 달리는 상호작용 알림을 사용자에게 전달해 응답성을 높인다.

## 2. 문제 정의
- 사용자는 자신의 게시글에 달린 댓글/답글을 즉시 확인하기 어렵다.
- 알림 대상이 게시글 단위로 정리되지 않으면 커뮤니티 재방문 유도가 약해진다.

## 3. 범위 (MVP)
### In Scope
- 일반/질문/투표 게시글에 달린 댓글 알림 생성
- 일반/질문/투표 게시글의 내 댓글에 달린 대댓글 알림 생성
- 커뮤니티 알림 목록에서 해당 알림 조회
- 알림 탭 시 관련 게시글 상세로 이동
- 읽음/안읽음 상태 관리
- 푸시 알림 수신(FCM) 및 인앱 알림 목록 동기화

### Out of Scope
- 좋아요/추천/조회수 알림
- 팔로우/멘션/쪽지 알림
- 운영자 공지성 알림
- 예약 발송/배치성 알림
- 알림 템플릿 다국어 운영

## 4. 핵심 사용자 플로우
1. A 사용자가 B 사용자의 게시글에 댓글을 작성한다.
2. 서버 측 이벤트가 알림 생성 조건을 확인한다.
3. 대상 사용자인 B에게 인앱 알림 레코드가 생성된다.
4. B의 FCM 토큰이 있으면 푸시 알림이 전송된다.
5. B가 알림을 누르면 해당 게시글 상세 화면으로 이동한다.

1. A 사용자가 B 사용자의 댓글에 대댓글을 작성한다.
2. 서버 측 이벤트가 알림 생성 조건을 확인한다.
3. 대상 사용자인 B에게 인앱 알림 레코드가 생성된다.
4. B의 FCM 토큰이 있으면 푸시 알림이 전송된다.
5. B가 알림을 누르면 해당 게시글 상세 화면으로 이동한다.

## 5. 알림 대상 규칙
- 모든 알림 항목에는 `일반 / 질문 / 투표`를 구분하는 chip을 표시한다.
- 게시글 작성자는 자신의 게시글에 달리는 댓글/대댓글/답변 알림을 받는다.
- 질문의 답변 작성자는 해당 답변에 달리는 직접 답글 알림만 받는다.
- 투표 작성자는 자신의 투표에 달리는 댓글 알림을 받는다.
- 투표 참여자는 `투표 종료` 시점의 알림만 받는다.
- 내가 댓글/답변을 남긴 질문이나 투표는, 내 댓글/답변에 직접 이어지는 답글만 알림으로 받는다.
- 게시글 전체의 모든 후속 활동을 참여자 전원에게 브로드캐스트하지 않는다.

## 6. 기능 요구사항 (FR)
- FR-NOTI-POST-01: 사용자가 자신의 게시글에 다른 사용자의 댓글이 달리면 알림을 받아야 한다.
- FR-NOTI-POST-02: 알림은 게시글 작성자에게만 전달되어야 한다.
- FR-NOTI-POST-03: 본인이 작성한 댓글에는 알림이 생성되지 않아야 한다.
- FR-NOTI-POST-04: 사용자가 자신의 댓글에 다른 사용자의 대댓글이 달리면 알림을 받아야 한다.
- FR-NOTI-POST-05: 일반/질문/투표 게시글 모두 동일한 알림 정책을 적용해야 한다.
- FR-NOTI-POST-06: 알림은 게시글 상세 진입 경로를 포함해야 한다.
- FR-NOTI-POST-07: 알림은 읽음/안읽음 상태를 저장해야 한다.
- FR-NOTI-POST-08: 알림 목록은 최신순으로 조회되어야 한다.
- FR-NOTI-POST-09: 투표 참여자는 투표 종료 시점에만 종료 알림을 받아야 한다.
- FR-NOTI-POST-10: 푸시 전송 실패가 발생해도 댓글 작성 자체는 실패하면 안 된다.

## 7. 데이터 계약(초안)
### 알림(Notification)
- notificationId: string
- recipientUserId: string
- actorUserId: string
- targetType: enum(`board_post`, `question_post`, `vote_post`)
- targetId: string
- commentId: string
- parentCommentId: string?
- type: enum(`post_comment`)
- title: string
- body: string
- isRead: boolean
- createdAt: timestamp
- readAt: timestamp?

### FCM 토큰(User)
- userId: string
- fcmTokens: string[]
- lastTokenUpdatedAt: timestamp?

## 8. 예외/에러 규칙
- 대상 게시글이 삭제되었으면 알림 생성은 건너뛰고 실패로 처리하지 않는다.
- 본인 게시글에 본인이 댓글을 단 경우 알림을 생성하지 않는다.
- 본인 댓글에 본인이 대댓글을 단 경우 알림을 생성하지 않는다.
- FCM 토큰이 없으면 인앱 알림만 남기고 푸시는 생략한다.
- 푸시 전송 실패는 비치명적 오류로 처리한다.

## 9. 비기능 요구사항 (NFR)
- NFR-NOTI-POST-01: 알림 생성은 댓글 저장 흐름을 지연시키지 않아야 한다.
- NFR-NOTI-POST-02: 알림 생성은 중복 방지를 고려해 멱등하게 처리해야 한다.
- NFR-NOTI-POST-03: 알림 데이터는 수신자 기준으로만 조회 가능해야 한다.
- NFR-NOTI-POST-04: 푸시 전송은 신뢰 가능한 서버 실행 환경에서 수행되어야 한다.

## 10. 수용 기준 (AC)
- AC-NOTI-POST-01: 내 게시글에 타인이 댓글을 달면 알림이 생성된다.
- AC-NOTI-POST-02: 내 댓글에는 알림이 생성되지 않는다.
- AC-NOTI-POST-03: 내 댓글에 타인이 대댓글을 달면 알림이 생성된다.
- AC-NOTI-POST-04: 알림 항목을 누르면 해당 게시글 상세로 이동한다.
- AC-NOTI-POST-05: 알림 목록에서 읽음 상태를 구분할 수 있다.
- AC-NOTI-POST-06: 푸시 토큰이 없더라도 댓글 작성은 정상 완료된다.
