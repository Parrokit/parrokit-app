# Community 신고 기능 FRD (초안)

## 1. 목적
커뮤니티 위반 가능 콘텐츠를 사용자 신고로 접수하고 운영 검토 체계로 연결한다.

## 2. 문제 정의
- 운영자 검토가 필요한 위반 콘텐츠를 접수하는 표준 신고 경로가 없다.
- 반복 신고/악의적 신고를 제어하는 기본 정책이 필요하다.

## 3. 범위 (MVP)
### In Scope
- 게시글/댓글/사용자 프로필 신고 접수
- 신고 사유 선택 및 상세 입력
- 신고 접수 결과 확인(접수 완료 상태)
- 중복 신고 방지(동일 사용자-동일 대상 기준)
- 신고 이력 최소 감사 필드 저장

### Out of Scope
- 자동 제재(자동 정지/자동 삭제)
- 고도화 탐지 모델(스팸/욕설 자동 분류)
- 운영자 콘솔 상세 UI
- 법적 요청 처리 워크플로

## 4. 핵심 사용자 플로우
1. 사용자가 게시글/댓글/프로필의 더보기 메뉴 진입
2. `신고` 선택
3. 사유 타입 선택(필요 시 상세 입력)
4. 신고 접수
5. 접수 결과를 토스트/배너로 확인

## 5. 기능 요구사항 (FR)
- FR-REPORT-01: 사용자는 게시글/댓글/프로필 단위로 신고를 접수할 수 있어야 한다.
- FR-REPORT-02: 신고 시 사유 타입(예: 스팸, 혐오/괴롭힘, 음란/폭력, 사칭, 기타)을 선택할 수 있어야 한다.
- FR-REPORT-03: `기타` 선택 시 상세 설명 텍스트를 입력할 수 있어야 한다.
- FR-REPORT-04: 동일 사용자가 동일 대상을 단기간 반복 신고할 경우 중복 접수를 제한해야 한다.
- FR-REPORT-05: 신고 접수 시 접수 ID와 접수 시각을 기록해야 한다.
- FR-REPORT-06: 신고 이력은 감사 추적이 가능하도록 최소 필드를 저장해야 한다.
- FR-REPORT-07: 신고 상태는 최소 `received`, `reviewing`, `resolved`, `rejected`를 지원해야 한다.

## 6. 데이터 계약(초안)
### 신고(Report)
- reportId: string
- reporterUserId: string
- targetType: enum(`post`, `comment`, `profile`)
- targetId: string
- targetOwnerUserId: string
- reasonType: enum(`spam`, `harassment`, `sexual_or_violent`, `impersonation`, `other`)
- reasonDetail: string? (`other`일 때 권장)
- createdAt: timestamp
- status: enum(`received`, `reviewing`, `resolved`, `rejected`)

## 7. 예외/에러 규칙
- 신고 대상이 삭제/비공개로 확인 불가하면 `대상 확인 불가` 에러를 반환한다.
- 신고 사유 누락 시 클라이언트 입력 검증 에러를 반환한다.
- 네트워크 실패 시 재시도 액션을 제공한다.

## 8. 비기능 요구사항 (NFR)
- NFR-REPORT-01: 신고 데이터는 수정 불가 append-only 로그로 보관되어야 한다.
- NFR-REPORT-02: 개인정보/신고 상세 내용은 권한 있는 관리자만 조회 가능해야 한다.
- NFR-REPORT-03: 악의적 대량 신고를 완화하기 위한 기본 rate limit 정책을 적용해야 한다.

## 9. 수용 기준 (AC)
- AC-REPORT-01: 게시글/댓글/프로필 각각에 대해 신고 접수가 가능하다.
- AC-REPORT-02: 신고 접수 시 사유 타입과 접수 완료 상태를 확인할 수 있다.
- AC-REPORT-03: 동일 대상 반복 신고는 중복 제한 정책에 따라 차단된다.
- AC-REPORT-04: 신고가 접수되면 추적 가능한 접수 ID가 생성된다.

## 10. 오픈 이슈
- 신고 사유 타입의 최종 다국어 문구 확정 필요
- 운영자 처리 SLA(예: 24시간 내 1차 검토) 수치 확정 필요
- 신고 누적 시 자동 임시 블라인드 임계치 도입 여부 확정 필요
