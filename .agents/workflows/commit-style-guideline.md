# 커밋 스타일 가이드

## 기본 규칙

1. 커밋 메시지는 항상 `[+]` 접두사로 시작한다.
2. 타입 접두사 필수: `feat/fix/refactor/docs/test/chore/ci/build/perf/style/revert`
3. 한국어로 간결하게 작성한다.

## 단일 항목 형식

1. `[+] {type}: {변경 요약}`
2. **Scope (괄호) 사용 금지**: `test(community)`처럼 `{type}` 뒤에 괄호로 범위를 지정하지 않는다. 오직 `{type}: ` 형태만 사용한다.

## 다중 항목 형식 (작업 범주 2개 이상)

1. 한 커밋 메시지 본문에 여러 줄로 작성한다.
2. 각 줄은 반드시 `[+] {type}: {변경 요약}` 형식을 따른다.
3. 첫 줄부터 마지막 줄까지 모든 줄에 `[+]`를 붙인다.

예시:

```text
[+] feat: 커뮤니티 보드 카드 분리
[+] refactor: 부트스트랩 초기화 단계 파일 분리
[+] docs: QA 로그 가이드 추가
```

## 작성 기준

1. 기능 단위로 커밋하고 메시지는 결과 중심으로 작성
2. 불필요한 영어/이모지/장문 설명 금지
3. 문서 동기화가 포함되면 요약에 문서 키워드 포함
4. 한 커밋에 여러 성격이 섞이면 다중 항목 형식을 우선 사용
