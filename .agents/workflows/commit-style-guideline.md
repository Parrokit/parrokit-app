# 커밋 스타일 가이드

## 기본 규칙

1. 한 줄 커밋 유지
2. 한국어로 간결하게 작성
3. 타입 접두사 필수

## 형식

1. `{type}: {변경 요약}`
2. 필요 시 scope 허용: `{type}({scope}): {변경 요약}`

## 허용 타입

1. `feat: {변경 요약}`
2. `fix: {수정 요약}`
3. `refactor: {구조 개선 요약}`
4. `docs: {문서 변경 요약}`
5. `test: {테스트 변경 요약}`
6. `chore: {잡무/설정 변경 요약}`
7. `ci: {CI 변경 요약}`
8. `build: {빌드/의존성 변경 요약}`
9. `perf: {성능 개선 요약}`
10. `style: {포맷/스타일 정리 요약}`
11. `revert: {되돌린 변경 요약}`

## 작성 기준

1. 기능 단위로 커밋하고 메시지는 결과 중심으로 작성
2. 불필요한 영어/이모지/장문 설명 금지
3. 문서 동기화가 포함되면 요약에 문서 키워드 포함
4. 한 커밋에 여러 성격이 섞이면 대표 타입 1개만 선택

## 예시

1. `feat: 커뮤니티 메뉴 구조 분리`
2. `fix: 질문 목록 필터 조건 오류 수정`
3. `refactor: AGENTS 규칙 간결화`
4. `docs: API 스펙 동기화`
5. `chore: 커밋 메시지 규칙 확장`
