# Development Workflow

## 기본 원칙

- 작업 전 관련 파일과 기존 구현을 먼저 확인한다.
- 기존 코드 스타일과 구조를 우선 유지한다.
- 불필요한 리팩터링은 하지 않는다.
- 변경 범위가 크면 작업 단위를 나누어 진행한다.
- 작업 중 발견한 문제는 실제 변경 범위와 관련 있을 때만 수정한다.

## 작업 진행

- 구현 전 변경 목적과 영향을 받는 범위를 파악한다.
- 기능 추가, 수정, 리팩터링은 가능한 한 분리한다.
- 기존 동작을 깨뜨릴 수 있는 변경은 신중하게 처리한다.
- 임시 코드, 테스트용 코드, 불필요한 로그는 남기지 않는다.
- 작업 후 변경 내용을 검토한다.

## 검증

- 변경 후 가능한 범위에서 최소 검증을 수행한다.
- 실행이 필요한 경우 관련 명령어를 우선 사용한다.
- 검증하지 못한 부분은 명확히 남긴다.
- 에러가 발생하면 원인과 수정 내용을 함께 정리한다.

## 커밋 전 정리

- 변경 파일을 확인한다.
- 변경 목적과 실제 변경 내용을 비교한다.
- 구현 시 `rules/architecture.md`의 아키텍처 규칙을 따른다.
- 커밋 시 `rules/commit-message.md`의 커밋 메시지 규칙을 따른다.
